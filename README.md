# tulaufa

Сайтик бежиного луга

## Требования

- Node.js 22 или новее (CI собирает на 22)
- npm

## Разработка

После установки зависимостей через `npm install` запустите сервер разработки:

```sh
npm run dev

# или запустите сервер и сразу откройте приложение в новой вкладке браузера
npm run dev -- --open
```

## Сборка

Чтобы собрать продакшен-версию приложения:

```sh
npm run build
```

Готовый сайт появится в каталоге `build/` (он в `.gitignore` — в репозиторий не коммитится).
Посмотреть собранную версию можно командой `npm run preview`.

## Как вносить изменения

Единственная долгоживущая ветка — `main`. Всё остальное создаётся под задачу и
удаляется после вливания.

1. Создайте ветку от свежего `main`:

   ```sh
   git switch main && git pull
   git switch -c feature/краткое-описание
   ```

   Префиксы: `feature/` — новое, `fix/` — исправления, `chore/` — рутина
   (конфиги, зависимости, CI), `docs/` — документация.

2. Перед коммитом убедитесь, что сборка проходит:

   ```sh
   npm run check     # проверка типов
   npm run build
   ```

3. Откройте PR в `main`. На каждый PR автоматически запускается workflow **CI**:
   он ставит зависимости, прогоняет `npm run check` и `npm run build`.
   Вливайте PR после ревью и зелёного CI.

Коммит в `main` напрямую ничего не выкатывает: деплой запускается только вручную,
см. ниже.

## Как выкатить релиз

Деплой всегда ручной и всегда с ветки `main`.

1. **Actions → deploy → Run workflow**, ветка `main`.
2. Запуск остановится со статусом «Waiting for review» — это гейт окружения
   `production`. Запросить аппрув у @indiagolph99.
 
Из командной строки то же самое:

```sh
gh workflow run "deploy" --ref main
```

История выкаток — во вкладке **Deployments** репозитория.

### Откат

Тег указывает на конкретный коммит, поэтому откат — это обычный откат кода:
верните `main` к нужному состоянию (через `git revert` и PR) и запустите деплой снова.
Отдельной кнопки отката нет (пока)
