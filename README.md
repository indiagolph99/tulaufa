# tulaufa

Статичный сайт [tulaufa.ru](https://tulaufa.ru) на SvelteKit с `adapter-static`:
страницы пререндерятся в HTML на этапе сборки, сервер раздаёт готовые файлы.

## Требования

- Node.js 22 или новее (CI собирает на 22)
- npm

## Разработка

После установки зависимостей через `npm install` запустите сервер разработки:

```sh
npm run dev

# или запустите сервер и сразу откройте приложение в новой вкладке браузера
npm run dev -- --open
```

## Сборка

Чтобы собрать продакшен-версию приложения:

```sh
npm run build
```

Готовый сайт появится в каталоге `build/` (он в `.gitignore` — в репозиторий не коммитится).
Посмотреть собранную версию можно командой `npm run preview`.

## Как вносить изменения

Единственная долгоживущая ветка — `main`. Всё остальное создаётся под задачу и
удаляется после вливания.

1. Создайте ветку от свежего `main`:

   ```sh
   git switch main && git pull
   git switch -c feature/краткое-описание
   ```

   Префиксы: `feature/` — новое, `fix/` — исправления, `chore/` — рутина
   (конфиги, зависимости, CI), `docs/` — документация.

2. Перед коммитом убедитесь, что сборка проходит:

   ```sh
   npm run build
   npm run check     # проверка типов
   ```

3. Откройте PR в `main` и влейте его после ревью.

Коммит в `main` напрямую ничего не выкатывает: деплой запускается только вручную,
см. ниже.

## Как выкатить релиз

Деплой всегда ручной и всегда с ветки `main`.

1. **Actions → Deploy to VPS → Run workflow**, ветка `main`.
2. Запуск остановится со статусом «Waiting for review» — это гейт окружения
   `production`. Подтвердите его.
3. После подтверждения workflow:
   - ставит зависимости (`npm ci`) и собирает сайт (`npm run build`);
   - синхронизирует `build/` с докрутом на сервере по `rsync` через SSH;
   - создаёт и пушит тег `v<ГГГГ.ММ.ДД>` — метку того, что уехало в продакшен.

Второй деплой в тот же день получит тег с суффиксом: `v2026.09.19.2`, `.3` и так далее.

Из командной строки то же самое:

```sh
gh workflow run "Deploy to VPS" --ref main
```

История выкаток — во вкладке **Deployments** репозитория.

### Откат

Тег указывает на конкретный коммит, поэтому откат — это обычный откат кода:
верните `main` к нужному состоянию (через `git revert` и PR) и запустите деплой снова.
Отдельной кнопки отката нет: сервер всегда приводится к тому, что лежит в `build/`.

## Как это устроено

- **Гейт и ограничение веток** заданы окружением `production`, а не проверками
  внутри workflow: у окружения есть required reviewer и deployment branch policy,
  разрешающая только `main`. Запустить деплой с другой ветки не получится —
  GitHub не даст стартовать заданию.
- **Секреты деплоя** (`SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS`, `DEPLOY_HOST`,
  `DEPLOY_PORT`, `DEPLOY_USER`, `DEPLOY_PATH`) живут на уровне окружения, а не
  репозитория: их видят только запуски, нацеленные на `production`.
- **На сервере** nginx раздаёт статику. CI ходит отдельным пользователем без
  пароля и без sudo, который владеет только каталогом сайта.
- **Ключи хоста закреплены** (`StrictHostKeyChecking=yes`). Если VPS пересоздадут,
  деплой упадёт — это ожидаемо. Нужно пересканировать ключи и обновить секрет
  `SSH_KNOWN_HOSTS`.
- **`rsync` работает с `--delete`**: докрут становится точной копией `build/`.
  Файл, который положили на сервер руками, будет удалён следующим деплоем.

> **Обратите внимание:** в этой версии SvelteKit нет `svelte.config.js` —
> адаптер и опции компилятора настраиваются в `vite.config.ts`.
